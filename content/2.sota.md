## Related work
{:#related-work}

Even-though imperative rewriting algorithms could suffice to cover the use-case of
query rewriting between SPARQL 1.2 and SPARQL 1.1 under a given reification scheme,
a generic and declarative approach introduces several advantages:
<!-- -->
1. adaptability to unknown reification scheme, 
2. interpretability of the declarative nature, and
3. reuse of existing skills
<!-- -->
To this end, we will not discuss an imperative algorithm that covers just our bounded use-case,
but instead consult the broader data integration literature.

**Global-as-View**
In the [tradition data integration literature](cite:cites lenzerini2002data), data integration is achieved though describing mappings.
These napping can either:
<!-- -->
1. Describe global view given your local sources (Global-as-Local (GAV)), or
2. describe your local sources given the global view (Local-as-View (LAV)).
<!-- -->

Applying this literature to RDF tends to be tricky.
Applying RDF to this existing data integration literature,
we say that the user writes a query over the _global schema_, while only the _source schemata_ are actually available.
Our goal is to equivalently rewrite the user query such that it targets the source schemata instead of the global schema.
Interestingly, RDF in its most general form is schemaless, meaning the schema is fixed, in relation to relational databases, we could say we have only a single relation, the tripels relation.
Additionally, a basic operation is the [dataset level merge operation](cite:cites spec:rdf-semantics-1-2),
which allows you to seamlessly merge RDF datasets.

In GAV, you describe an element of the global schema with only a single mapping,
while in the case of LAV, you describe each element of each local schema using a single mapping.
This is a source of much confusion, because you can describe the relation of each source to the global using a single query; and this is typically what one would do.
However, the full definition of the mapping towards the global neccesitates that you have only one query.
What is implicitly being done, is adding the union operation between all sources; resulting in a single mapping to describe the global.
