## Demonstration
{:#demo}

In this demonstration,
users can perform federated queries over self chosen sources incorporating mappings that they can construct themselves.
The user interface exists of four panels each with their own purpose.

The _mappings panel_ on the top left allows users to manage their mappings that define the global.
As discussed in [](#gav-lav) only one mapping is allowed;
when providing multiple mappings we implicitly perform the dataset union operation,
note that for performance reasons we disregard the set semantics of RDF-datasets and instead perform a bag-union.

<figure id="mapping" style="display: flex; flex-direction: column">
<pre><code># Create a mapping from rdf reification to triple terms
CONSTRUCT { ?t rdf:reifies <<( ?s ?p ?o )>> } WHERE {
  ?t a rdf:Statement ;
     rdf:Subject ?s ;
     rdf:Predicate ?p ;
     rdf:Object ?o ; 
} # and copy all triples
CONSTRUCT { ?s ?p ?o } WHERE {
  ?s ?p ?o .
}</code></pre>
<figcaption markdown="block">
Two mappings, one creates the triple term in the global,
the other simply maps all source triples to the global.
</figcaption>
</figure>


<figure id="mapping-as-one" style="display: flex; flex-direction: column">
<pre><code>CONSTRUCT { ?s ?p ?o } WHERE {
  { ?m_t a rdf:Statement ;
       rdf:Subject ?m_s ;
       rdf:Predicate ?m_p ;
       rdf:Object ?m_o .
    BIND(?m_t as ?s) .
    BIND(rdf:reifies as ?p) .
    BIND(triple(?m_s, ?m_p, ?m_o) as ?o). }
  UNION
  { ?s ?p ?o }
}</code></pre>
<figcaption markdown="block">
The same mapping as [](#mapping) but written using only a single mapping - in accordance to [](#gav-lav).
</figcaption>
</figure>


<figure id="user-query" style="display: flex; flex-direction: column">
<pre><code>SELECT * WHERE {
  ?t rdf:reifies <<( ?s rdf:type ?o )>> ;
     ex:confidence ?score .
  FILTER(?score > 0.8)
}</code></pre>
<figcaption markdown="block">
An example user query requesting any triple term with predicate `rdf:type`
which has a confidence score higher than 0.8.
</figcaption>
</figure>


<figure id="rewritten-query" style="display: flex; flex-direction: column">
<pre><code>SELECT ?level ?o ?s ?t WHERE {
  { ?t rdf:type rdf:Statement ; rdf:Subject ?s ;
       rdf:Predicate rdf:type ; rdf:Object ?o . }
  UNION { # Assume 1.1 sources -> no triple terms
    FILTER ( FALSE ) }
  { # Predicate rdf:reifies does not match ex:trust-level
    FILTER ( FALSE ) }
  UNION {
    ?s ex:trust-level ?o .
  }
  FILTER ( ?uq_level &gt; 0.8 )
}</code></pre>
<figcaption markdown="block">
A, for interpretability, cleaned up version of the query in [](#user-query) over the global defined by [](#mapping-as-one).
A normal UNION is taken, instead of the set UNION for optimization purposes.
</figcaption>
</figure>

The _query panel_ on the top right allows users to manage their sources and write the query.
When providing no sources, the re-written query can still provide results when the mappings use SERVICE calls in their 
mapping bodies.
Additionally, when providing many sources,
the federation engine will function under [automatic source selection](cite:cites),
which in it of itself can be seen as a GAV rewriting where each mapping is of the form
`CONSTRUCT { ?s ?p ?o } WHERE { SERVICE <serviceA> { ?s ?p ?o } }`, causing two layers of GAV rewriting.
The query panel also provides the opportunity to load some example settings:
<!-- -->
1. thrust-worthiness using RDF 1.2, 
2. automatic source selection, and
3. spam-filter.

The _rewritten query panel_ is a readonly panel which shows, after execution,
the rewritten user query obtained by performing the unfolding.

Finally, the _results_ panel shows
the running execution time,
the number of results
and the stream of results as they arrive.
